# 三道硬闸的设计依据与事故清单（pipeline-and-gates）

本 skill 的防错原则：**参数错就拒绝执行，绝不产出"看起来对"的烂文档**。所有闸门都来自 2026-09 真实事故。

## 事故 1（2026-09-21）：旧数据套今天的标题

- 现象：文档标题"· 2026-09-21"，内装 9/17→9/18 的 166 条旧闻
- 根因链：cron 重复投递 → agent 复用上下文残留的旧 `--since` → 脚本 doc_title 恒取系统今天、与窗口零校验脱钩 → 错误畅通无阻上云
- 修复：**窗口闸**（since 距今>1 天或为未来即拒绝）+ cron 提示词"先跑 date 校准、禁止沿用旧值"

## 事故 2（同日）：数据站停更误判

- 现象：用户质疑"消息是不是老的、数据站是不是停了"
- 处置：查 `/v1/status`（最后刷新轮次 14:33→14:45、94 源计划 87 成功、土源全 ok）——**用证据回答，不擅自重跑**
- 修复：**新鲜度闸**（窗口内最新条目非今天即拒绝并提示查 status）+ 记忆条目"用户提问只回答，不跑任务"

## 事故 3（2026-10-08 回溯发现）：两天执行缺口

- 现象：10/6、10/7 两天任务无执行记录（机器未开机/投递中断），直接跳到 10/8 的 16h 窗口会漏掉两天新闻
- 处置：按铁律仍只跑标准 16h 窗口，**汇报中明确缺口**，补做需用户确认（不擅自扩大窗口）

## 事故 4（2026-10-01）：重复投递连发三版

- 现象：同一天产出三份同名文档（旧闻版/摘要残缺版/修正版），用户无法分辨
- 修复：**一天一份闸**（build_state.json 记录当日 prod_date/file_id/url，重复构建拒绝；重复 cron 直接回已有链接）+ 摘要为空拒绝（第二版"重点消息包括：、、、"的根因是中文标题漏填）

## 事故 5（2026-10-01）：时钟漂移错档

- 现象：fetch 时 15:03 生成档 20260921_2303，build 时 15:15 重算窗口变成 2315 → FileNotFoundError
- 修复：`build --hours 16` 不再掐表，**自动挂接数据目录里最新的 `*_items.json` 档**

## 事故 6（贯穿多日）：编译错配家族

| 错误 | 检出方式 | 修复 |
|------|---------|------|
| 来源写串（cnbce/foreks/dunya） | 对账 leftover | 按提示修 |
| 时间 ±1 分钟笔误 | 对账 leftover | 按提示修 |
| 同分钟成组漏 key → 张冠李戴 | 人工对读 | 补真实子串 key |
| â（kâr）不在折叠表 | 对账 leftover | 换真实子串 |
| 幻影条目（昨日新闻写成今日） | 对账 leftover | 删除 |
| 一条错配吞掉另一条的翻译（数量恰好平衡） | 按组对账 (time,source) 计数 | 逐组核对 |

教训：**条数一致 ≠ 没有错配**。merge_zh_parts.py 同时做条数断言、leftover 清零、空标题拒绝，三者全过才生成 `_zh.json`。

## 闸门实现位置（scripts/tr_daily.py）

- 窗口闸：`check_window()`
- 新鲜度闸：`cmd_build()` 内 `newest[:10] != prod_date`
- 一天一份闸：`cmd_build()` 读 `build_state.json`；成功发布后写回
- 附加闸：items=0 拒绝、空中文标题拒绝、空摘要拒绝
- 绕过：`--force` 仅限用户当条消息明确要求时使用
