# 中文编译与分级规范（zh-translation-spec）

fetch 生成的 `tr_data/<tag>_zh.json` 模板每条为五列：

```
[time(HH:MM), source_id, key, tier, 中文标题]
```

## 分级标准（tier，重要性 = 对国际或土耳其股市的影响）

| tier | 级别 | 判定 |
|------|------|------|
| 0 | 🔴 高 | 宏观数据（CPI/PPI/PMI/就业）、央行/财政/货币政策表态、地缘与油价直接冲击里拉/BIST、市场监管重拳（卖空限制/停牌/接管） |
| 1 | 🟠 中 | BIST 个股与券商研判、资金与制度动向、重要全球宏观背景、大型并购/IPO |
| 2 | ⚪ 低 | 公司披露、软新闻、娱乐体育、噪音 |

规则：
- 事件簇只给主条目高分级，后续/转述条目降一档，第三条起给 2
- 关键词初筛（脚本 AUTO 标记）只是初筛，agent 必须逐条人工复核改级
- 全部条目必须填完，中文标题不允许留空（build 会拒绝空标题）

## 中文标题写法

- 一句话说清"谁/发生了什么/关键数字"，面向中国读者（专有名词可保留原文公司名）
- 慎用感叹号；不写"突发"字样（分级已表达）；数字保留原文精度（如 4.5万亿里拉、782%）

## key 规则（最容易翻车的一列）

- **仅当同一时刻同一来源有多条时才填 key**；单条条目一律 `key=""`
- key 必须是**该条文本/URL 经 ASCII 折转写后的真实子串**，逐字符照抄，绝不允许自造、编号、缩写
- 土耳其字符折叠表：`ı/İ→i`（注意 `İ`.lower() 会产生 `i+U+0307`，脚本已处理）、`ç→c`、`ğ→g`、`ö→o`、`ş→s`、`ü→u`
- 常见事故（都会真实发生）：
  - **来源写串**：cnbce/foreks/dunya 互相写错 → 成批失配。对账脚本会报 leftover，按提示修
  - **时间笔误**：±1 分钟（13:05 写成 13:06）→ 单条 leftover。同分钟成组时极易抄错行
  - **扬抑符 â 不在折叠表**：如 `kâr` 无法折成 `kar` → 换一个不含 â 的真实子串做 key
  - **带撇号词**：`Gazete'de` 折转后保留撇号，key 必须含撇号或避开该词
  - **幻影条目**：把前一天窗口里见过的同标题新闻当成今天的写进来 → 对账时它匹配不到条目。删掉即可
- 校验工具：`python scripts/merge_zh_parts.py --tag <tag> --parts "_zh_*.json"` —— leftover=0 且条数一致才放行 build

## 分片写大文件（防截断）

Write 工具写 >20KB 的 JSON 会静默截断。做法：
1. 按 20-40 条一片写成 `_zh_<日期>_a.json / _b.json / ...`
2. 每片末尾放一条 `["占位…（合并脚本会剔除）"]` 哨兵——若哨兵丢失说明该片被截断
3. `scripts/merge_zh_parts.py` 合并 + 剔除占位 + 对账
