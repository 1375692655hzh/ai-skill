# 土耳其股市热点日报 Skill

## 1. 任务目标

当用户要求“生成今天的土耳其股市日报”“按之前格式做日报”或自动化触发本 Skill 时：

1. 识别本次报告日期。
2. 读取本次最新资料包。
3. 严格按照本 Skill 的筛选与来源规则生成日报。
4. 输出 Word（`.docx`）。
5. Word 必须完成 render → inspect → fix（如需）→ re-render 的完整质检后才能交付。

默认输出文件名：

`turkey_daily_YYYYMMDD.docx`

语言：简体中文。

---

## 2. 预期输入文件

常见文件名如下，实际以当天上传/项目文件为准：

- `YYYY-MM-DD_info_daily_report_zh.md`
- `YYYY-MM-DD_daily_briefing_zh.md`
- `YYYY-MM-DD_x_influencer_full_zh.md`
- `YYYY-MM-DD_aa_morning_briefing_zh.md`
- `YYYY-MM-DD_info_technical_report_zh.md`（可选）
- `PREV-DATE_close_report_zh.md`
- `PREV-DATE_close_report_fallback_zh.md`（仅正式收评缺失时备用）
- `PREV-DATE_paraborsa_all_report_zh.md`

### 日期识别

报告日期优先从以下“当日资料”中取一致日期：

1. `info_daily_report`
2. `daily_briefing`
3. `x_influencer_full`
4. `aa_morning_briefing`

前一交易日的 `close_report` 与 `paraborsa` 只作为前一交易日收盘/券商背景，不应错误写成当日数据。

若周一遇到周末，前一交易日可能是周五，按真实交易日处理，不机械减一天。

## 3. 来源与日期纪律

### 3.1 只用本次资料包

除非用户明确要求联网核查或补充：

- 不调用外部网页补写。
- 不从旧日报、旧资料包中拿内容补空缺。
- 不把前几天的技术位、观点、事件重新包装成今天的新观点。
- 当前 X 大V文件的滚动窗口（通常约34–35小时）可以覆盖前一日内容，但必须按本 Skill 的“延续判断规则”使用。

### 3.2 正式收盘优先

若同时存在：

- 盘前/实时快照；
- fallback 收评；
- 正式收评；

则优先级为：

**正式收评 > after_close 实时收盘快照 > fallback > 盘前快照。**

不得拿盘前 XU100 数值当作前一交易日最终收盘。

### 3.3 Paraborsa 口径

Paraborsa 通常是前一交易日发布的券商晨报/盘中观点。

若报告日期为 T，Paraborsa 文件日期为 T-1：

- 可以作为“前一交易日券商观点/背景”。
- 不得写成“今日券商认为”。
- 若当天 Info Yatırım 已有新判断，优先用当天 Info。
- 前一交易日券商技术位若已被最新行情明显穿越，不应继续作为当前核心点位；可写成背景，但要说明日期。

### 3.4 数据单位

若中文源文件对“bn / milyar / 亿”等单位存在明显歧义：

- 不擅自换算。
- 优先写“成交明显放大/缩量”“资金净流入/流出明显”等。
- 只有原始单位明确、可核实时才写精确数字。

## 4. 固定报告结构

日报只保留两个主章节：

# 一、热点资讯

# 二、个股分析（仅保留有实质判断的标的）

不要额外增加：

- 今日关注方向
- 今日策略
- 大V汇总
- 热门股
- 重点推荐

### 标题

居中：

`土耳其股市热点日报｜YYYY年M月D日`

副标题示例：

`前一交易日收盘 + 周五盘前/早盘 + 当日大V观点`

资料范围说明控制在 1 段内，说明：

- 使用了哪些文件；
- X窗口范围与帖子数；
- 若重要大V抓取失败，可说明。

---

## 5. 第一部分：热点资讯

### 5.1 数量

通常 5–7 条，不固定。

相关信息应合并，不要为了凑条目拆成很多碎点。

### 5.2 推荐排序

优先级通常如下：

1. 大盘收盘 + 当前关键技术区间
2. 国内基金清算 / SPK / 监管 / 支付 / 流动性
3. 资金流 / 外资 / 机构买卖 / 市场结构
4. 全球利率 / 美债 / 美联储 / 欧债
5. 地缘 + 原油
6. 重要行业数据
7. 对市场有明显影响的个股重大合同、财报或事件

顺序可根据当日重要性调整。

### 5.3 每条固定三个字段

每条必须是：

**事件介绍：**
- 客观事实。
- 不写博客腔。
- 不夹带助理主观看法。
- 不写大V名字，除非事件本身就是大V访谈/公开声明且必须归因。

**影响分析：**
- 可以写大V名字。
- 先写大V原始判断，再做简短整合。
- 不把助理推断冒充成大V原话。

**券商观点：**
- 优先当天 Info Yatırım。
- 若只有前一交易日 Paraborsa，明确写“前一交易日券商观点”。
- 不拼接过期点位当成今日新观点。

---

## 6. 第二部分：个股分析

### 6.1 固定表格

只允许 4 列：

| 股票名称 | 定位 | 投资决策 | 大V分析观点 |
|---|---|---|---|

不要增加：

- 行业
- 事件
- 技术面
- 估值
- 支撑/压力单独列
- 热度
- 涨跌幅

### 6.2 核心原则

**绝对不要只挑热门股。**

必须扫描当前 X 大V全文里的 **全部账号、全部帖子**。

只要大V对某只股票给出“实质判断”，即使是冷门股、小盘股、低成交股，也应纳入。

不要因为某股票不热门、不在成交额前列就忽略。

---

## 7. 什么叫“实质判断”

满足下列任意一项即可考虑入表：

### 7.1 技术判断

有明确文字判断，例如：

- 支撑位 / 阻力位
- 通道上沿 / 下沿 / 中轨
- 50/100/200日均线位置
- 突破/跌破后的条件判断
- 明确的形态成立条件
- 明确的趋势转折条件

### 7.2 基本面判断

例如：

- 收入 / 利润 / 现金流 / 负债结构
- 订单、产能、出口、成本变化
- 资产结构、净现金、债务压力
- 经营改善/恶化的具体逻辑

### 7.3 资金 / 筹码 / 托管结构判断

例如：

- `takas` / 托管结构发生显著变化
- 具体机构持续建仓/减仓，并给出意义判断
- 流动性枯竭、卖方衰竭、机构结构变化等明确解释

注意：**单纯一张资金净流入/净流出排行榜不算。**

### 7.4 事件影响判断

例如：

- 被某指数调入/调出，明确解释被动买卖影响
- 大额合同，且大V明确解释对公司/股价的意义
- 要约收购、自由流通比例变化
- 监管调查、清算、债券违约等，并有具体公司风险判断

### 7.5 明确交易逻辑

例如：

- “突破X后重新进入上升通道”
- “若守不住X则下一位置看Y”
- “当前低估来自A/B/C，核心风险是D”
- “该股虽然回撤，但筹码结构/订单/资产负债表仍支持某逻辑”

### 7.6 多维估值判断

可以纳入：

- 市值 + 净资产 + PE/PB + 现金/负债 + 增长等多维组合分析。

不可以纳入：

- 只有“便宜/贵”
- 只有单一市值/账面价值比较
- 只有一个PE数值没有解释

---

## 8. 明确排除项

以下内容 **不能单独进入个股表**：

1. 只有 ticker / 公司名
2. ticker + 图片，无文字结论
3. 单纯K线图截图，没有文字说明
4. 单纯资金流入/流出排名
5. 单纯成交额排名
6. 单纯涨跌幅榜
7. 基金持仓名单
8. 机构模型组合名单但没有理由
9. “每日推荐：A/B/C”但没有具体原因
10. “持有5年/长期买入”一类泛泛名单
11. 单纯公司公告，没有大V解释其意义
12. 只有视频标题，没有可核对转录内容
13. 快速估值“便宜/贵”标签
14. 不具名股票分析，无法确定ticker
15. 基金代码/基金本身，不是上市股票

### 视频

若帖子只有：

`#CWENE KISA VADE ANALİZ!`

但没有视频转录中的支撑、阻力或判断：

- 不纳入。
- 不自行猜视频内容。

### 图片

若帖子只有：

`#ASELS #aselsan` + 图片

- 不纳入。
- 不自行从图上读取技术位后冒充大V原文。

## 9. “平衡筛选”规则：避免一只大V刷屏

这是最重要的补充规则。

X大V文件通常覆盖约34–35小时，因此可能包含前一日大量集中技术扫盘。

不能因为某个大V前一天一次性发了20–30只股票，就在今天的日报里把这一批全部重复搬进来。

### 正确规则

一只股票满足以下组合时，可把前一日的具体判断合并进今天：

**当天有新信息 + 当前X窗口内已有具体判断。**

“当天新信息”包括：

- 当天大V再次跟踪
- 当天出现新事件
- 当天出现重要资金异动
- 当天出现重大公告/合同/指数调整
- 当天出现明显价格/成交结构变化
- 当天被其他大V重新讨论

此时可把窗口内前一日的具体技术位/基本面观点合并，形成完整判断。

### 不应纳入

- 只有前一日旧技术位，今天没有任何新信息。
- 某大V前一日批量扫盘，今天完全没再提。
- 只是为了让表格数量多而重复旧观点。

### 结果数量

不设硬性只数。

可能是 3 只，也可能是 12 只。

标准只有一个：

**有实质判断就放，没有就不凑。**

不能为了“多样化”硬凑不同大V，也不能因为某天只有一个大V给出有效个股分析就虚构其他来源。

---

## 10. 多大V合并规则

若同一股票被多个大V讨论：

- 合并到同一行。
- 明确写出各自观点。
- 若观点冲突，保留冲突，不强行统一。
- 不重复做多行。

示例：

`TUPRS | 炼化/油价敏感 | 观察388突破 | Murat给出366/345支撑、388阻力；Tardu当日记录资金净流入，但资金流本身只作为辅助，不单独构成结论。`

---

## 11. 调查、操纵、违法类内容

涉及：

- 基金调查
- 操纵
- 非法获利
- 欺诈
- 监管调查
- 司法程序

必须使用归因式表达。

例如：

- “Barış支持的调查建议中点名……”
- “Tardu转述司法部长称……”
- “该观点属于监管风险提示，未代表监管已最终认定公司违法。”

禁止写成：

- “该公司操纵股价”
- “该公司违法”
- “该公司诈骗”

除非源文件明确记录监管/法院已经作出最终认定。

政治与公共政策内容保持中立、事实化。

---

## 12. 个股表“投资决策”写法

投资决策列不要过度武断。

优先使用：

- 关注
- 观察
- 谨慎
- 高风险观察
- 等待突破
- 等待支撑确认
- 等待调查结果
- 等待流动性恢复
- 不追涨
- 规避追高
- 观察事件兑现

只有当大V原文明确给出买入/卖出且理由完整时，可以写：

- “大V倾向买入”
- “大V建议止损”

但不要把助理自己的判断写成明确买卖指令。

---

## 13. 大盘点位规则

大盘点位来源优先级：

1. 当天 Info Yatırım 最新技术判断
2. 当天 daily briefing / technical report
3. 前一交易日 Paraborsa 共识
4. 大V指数技术观点

若不同来源冲突：

- 不强行混成一个数字。
- 以时间更新更晚者为主。
- 可写“Info看X，前一交易日券商共识为Y”。

不得自己画线推算支撑/阻力。

---

## 14. 写作风格

### 必须

- 简体中文
- 专业、简洁、克制
- 像正常财经日报，不写成研究报告长文
- “发生—原因—怎么看—影响”逻辑清楚
- 一个热点 3 个短段即可

### 避免

- AI总结腔
- 刻意拔高
- 口号式结尾
- 疑问句标题
- 过多模板转折
- “不是……而是……”
- “因此……”
- “更值得看的是……”
- “真正决定……”
- “兄弟们”
- “看好=重仓”
- “真正恐怖的是……”
- “盘完才发现……”

## 15. Word排版要求

生成 `.docx` 时：

- A4
- 字体：`Noto Sans CJK SC`
- 标题居中
- 正文简洁
- 4列表格不使用花哨底色
- 表头加粗
- 表格跨页时重复表头
- 单行尽量不拆页
- 不让第二页只剩一小块表格
- 文件名尽量使用短英文，避免下载兼容问题：

`turkey_daily_YYYYMMDD.docx`

### 强制质检

创建/修改DOCX必须使用DOCX技能中的完整流程：

1. 生成DOCX
2. 使用 canonical renderer 渲染：
   `python /home/oai/skills/docx/render_docx.py <input.docx> --output_dir <out_dir>`
3. 打开并检查每一页PNG
4. 检查：
   - 无截断
   - 无重叠
   - 无乱码
   - 表格不破
   - 页眉页脚正常
   - 行距正常
5. 若有问题，修复并重新渲染
6. 最后只交付DOCX，除非用户要求中间PNG/PDF

禁止在没有实际渲染检查时声称“已渲染检查”。

- [ ] 最终文件路径是否实际存在

## 17. 自动化执行逻辑

自动化触发时：

1. 找到最新一组当日资料。
2. 如果核心文件缺失，不要用旧文件硬补：
   - `info_daily_report`
   - `daily_briefing`
   - `x_influencer_full`
3. 若仅缺 `aa_morning_briefing`，可以继续生成，但在资料范围中注明缺失。
4. 若前一交易日正式收评缺失：
   - 使用 `after_close` / fallback；
   - 明确说明口径。
5. 若 X 大V文件完全缺失：
   - 不生成“个股大V分析表”的虚假内容；
   - 明确提示“X大V资料缺失，个股表无法按既定标准完成”。
6. 完成后输出DOCX下载链接。
7. 若需要自动化消息摘要，附一句：
   `已生成 YYYY-MM-DD 土耳其股市热点日报，个股表共N项。`
